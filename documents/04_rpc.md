# 04. RPC (초보자용)

## 1) RPC가 뭐예요?

RPC(Remote Procedure Call)는 **“멀리 있는 컴퓨터의 함수(메서드)를 호출한다”**는 방식입니다.

가장 쉬운 비유:
- 로컬에서는 `add(1, 2)`를 부르면 바로 결과가 나오죠.
- RPC에서는 `add(1, 2)`를 “네트워크 너머 서버에 요청”해서 결과를 받는 느낌입니다.

---

## 2) 기본 동작 방식(요청/응답 흐름)

RPC는 보통 이런 흐름을 가집니다.

1. 클라이언트가 “호출하고 싶은 함수 이름 + 파라미터”를 준비
2. 네트워크로 서버에 전송(HTTP, TCP 등 다양한 방식 가능)
3. 서버가 해당 함수를 실행
4. 결과를 응답으로 돌려줌

중요 포인트:
- REST처럼 “자원(Resource)” 중심이 아니라,
- **“행위(동작/명령)” 중심으로 모델링**되는 경우가 많습니다.

---

## 3) REST와 비교하면 뭐가 달라요?

- REST는 보통 URL이 자원에 가깝습니다: `/users/1`
- RPC는 보통 URL/메서드가 “행동”에 가깝습니다: `/rpc/add`, `/rpc/pay`

또한 RPC는 “메서드 이름/입력/출력”이 명확해서,
팀 내부 서비스끼리 통신할 때 편하다고 느끼는 경우가 많습니다.

---

## 4) 간단 예시(HTTP로 RPC 느낌 내기)

예를 들어 서버에 “add”라는 함수를 원격 호출한다고 해보면:

요청:
- `POST /rpc/add`

요청 바디 예:

```json
{
  "a": 1,
  "b": 2
}
```

응답 예:

```json
{
  "result": 3
}
```

> 이 방식은 “진짜 RPC 표준”이라기보다는, HTTP 위에서 RPC 스타일로 구성한 예시입니다.

---

## 5) 언제 RPC 스타일이 어울릴까요?

- “자원”보다 “행동(업무 명령)”이 중심인 경우
  - 예: 결제 승인, 포인트 차감, 재고 예약
- 내부 마이크로서비스 간 통신에서 “메서드 호출 느낌”이 필요할 때
